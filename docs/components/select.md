# `PctSelect` / `PctMultiSelect` — choice list with a panel of its own

**Entrypoint:** `@pacit/components/select`
**Selector:** `pct-select`, `pct-multi-select`
**Status:** released
**ARIA APG pattern:** [Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) — the
**select-only** one by default and the **editable, list-autocomplete** one with `filterable`:
`role="combobox"` on the trigger plus `role="listbox"` in the panel, **focus stays on the
trigger** in both, the active option through `aria-activedescendant`

Not a native `<select>`, because the native one gives no panel whose look and content can be
controlled — a deliberate exception to
[`req-api-platform`](../requirements/api.md#req-api-platform).

**Two tags, one implementation.** `pct-multi-select` holds a list of values; everything else
about it — the panel, the walk, the groups, the chrome, the slot — is the same template, the
same stylesheet and the same base class. It is a second tag rather than a `multiple` input
because an input is a value at runtime and cannot decide what `value` is: measured, and the
measurement is in [0034](../decisions/0034-multiplicity-is-a-tag.md). **Filtering is an input
on both**, and by the same rule read the other way — a tag is what the type cannot say
otherwise, and a filtering select's value is a select's value
([0035](../decisions/0035-a-filter-is-a-question-not-a-value.md)).

## Contract

|                 |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Value**       | `pct-select`: `T \| null`, generic; `value` and `emptyValue` as `NoInfer<T>` — the type comes **from the option list alone**. `pct-multi-select`: `T[]`, and no `emptyValue` — the empty list is `[]`, which every `T` can reach. The array type is mutable because that is how an application declares such a field (`signal<string[]>`, `FieldTree<string[]>`); nothing here mutates one, every change sets a new array. Chosen values come back **in the order of the list**, so the same set of choices is the same array however the picking went; a value no option carries is kept, ahead of the ones the list can order                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Options**     | `{ value, label, disabled? }`, or a **group** — `{ label, options, disabled? }` — and the two mixed, options before the first heading being what a native `<select>` draws above its first `<optgroup>`. An entry whose `options` is an array is a group; a group with none is drawn by nobody. `disabled` on a group reaches every option below it and does **not** rewrite them, so a consumer's own objects come back unchanged. **The values are unique** under `compareWith` — a value points back at one option (the first match), so the later of a duplicated pair is unreachable. Reported in dev mode, not repaired ([`lesson-66`](../lessons.md#lesson-66)). The panel loop tracks the row's position, every binding of a row being a function of it. **A heading is not a stop on the walk**: the options are numbered across the whole list, so the arrows, `Home`/`End`, typeahead and `aria-activedescendant` all read one list however many headings stand in it                                                 |
| **Inputs**      | `options`, `value` (`model`), `label`, `hint`, `ariaLabel`, `ariaLabelledby`, `placeholder`, `size`, `compareWith`, `emptyValue`, `panelWidth`, `panelAlign`, `filterable`, `filterText` (`model`), `filterWith`, `clearable`, `loading`, `virtual`, plus `FormUiControl`. **The two tags declare the same set but for `emptyValue`**, and that is measured off `ɵcmp.inputs` after a build rather than kept in step by hand (`libs/components/select/src/multi-select.spec.ts`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Naming**      | `ariaLabel` / `ariaLabelledby` are **inputs and not attributes on the tag**: `role="combobox"` sits on the trigger, the host carries no role, and an ARIA name on a roleless element is ignored. They reach the trigger and the panel, and win over `label` — the accessible-name algorithm, not a choice of ours (`tools/check-aria.mjs`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Panel**       | `panelWidth`: `"field"` (the default) \| `"auto"` \| a CSS length; `panelAlign`: `start` \| `center` \| `end`; one running off the viewport is pushed back in (`push`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Filtering**   | `filterable` turns the trigger into a text field and narrows the list to what is typed. **The question narrows the panel and never the value** ([0035](../decisions/0035-a-filter-is-a-question-not-a-value.md)): a chosen option the letters hide is still the one the trigger names, and a many-choice pick still writes the list's order. While the panel is open the field holds the question and the chosen label stands behind it as the `placeholder`; closing, and a pick on a many-choice list, take the question back — it never outlives the panel it was asked in. `filterText` is a `model`, so a list narrowed on a server reads the question and answers it with another `options` list. `filterWith` decides what counts as a match and takes the **option**, not the label; the default folds case and does **not** fold accents, because whether an accent is a letter of its own is a question of language and not of formatting ([`lesson-101`](../lessons.md#lesson-101))                                   |
| **Clearing**    | `clearable` draws a cross that takes back **what the trigger is showing** ([0036](../decisions/0036-a-clear-takes-back-what-the-trigger-shows.md)): the answer, or — while a filtering panel is up — the question being typed, the value and the panel standing. It is drawn only where there is something to take back, read off the trigger's own text: a value no option names shows nothing, so it offers to undo nothing. The cross stands **beside** the trigger and not inside it, because a `<button>` may hold no interactive content and the HTML parser splits the nesting into two siblings while a framework building the same template nests it ([`lesson-104`](../lessons.md#lesson-104)); it is **out of the tab order**, as the platform's own clear control is in all three engines, and the keyboard's way to the same thing is `Escape` over a shut panel. Off by default                                                                                                                                    |
| **Loading**     | `loading` says the list is on its way, and it is a fact about the **list** ([0037](../decisions/0037-loading-is-a-fact-about-the-list.md)): it disables nothing, closes nothing, keeps the answer already given and keeps the rows from the last answer on the screen. The panel carries `aria-busy` — which is also what makes an empty listbox legal, since `role="listbox"` owning no `role="option"` is a **critical** `aria-required-children` ([`lesson-106`](../lessons.md#lesson-106)) — and an empty one says `selectLoading` instead of concluding "no options" or "no matches". The keyboard cursor follows its option across an answer that replaces the list, by `compareWith` ([`lesson-107`](../lessons.md#lesson-107)); a list answered by a server is already narrowed, so that control's `filterWith` is `pctKeepAll`                                                                                                                                                                                          |
| **Window**      | `virtual` draws only the rows the panel can show, and it is a promise about **how many rows exist** — five thousand options are eleven elements and a press that answers in 15 ms instead of 626 ([0038](../decisions/0038-a-window-is-measured-and-its-spacer-is-not-an-element.md)). The listbox stays the element that scrolls, because the exemption keeping a panel of unfocusable rows out of `scrollable-region-focusable` is for a combobox's own popup; the rows nobody drew are held by a **pseudo-element**, since padding does not scroll and a spacer would be a child the listbox does not own. Every row carries `aria-setsize` and `aria-posinset` then — the DOM no longer holds the set, and no audit asks for them. The row's height is **measured**, not declared: it falls out of the type, `offsetHeight` rounds it and a rounded row is 2,027 px of wrong scrollbar over five thousand ([`lesson-108`](../lessons.md#lesson-108)). Off by default — a row that is not in the DOM is not found by `Ctrl+F` |
| **Parts**       | `trigger`, `value`, `placeholder`, `arrow`, `clear` (only while there is something to take back), `panel`, `group`, `group-label`, `option`, `option-check` (a chosen row of a **many-choice** list), `empty`, `label`, `hint`, `error`. On a **filtering** control `trigger` is the `<input>` — it keeps the role, the border and the ring — and `value` / `placeholder` do not exist: they are that input's own properties, and an element carries one part                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Slots**       | `pctSelectOption` — an `<ng-template>` a consumer writes to draw the option row instead of the built-in label. The context is `{ $implicit: option, index, active, selected, disabled }` — `index` counting across the headings and `disabled` being the row's, so an option inside a disabled group arrives disabled. Typed by a guard whose inference site is the slot's own **required** binding, which takes the same list the control does, groups included, so the list is given twice on purpose and the second one is read by nothing ([0027](../decisions/0027-a-slot-is-a-directive.md)). It replaces what is **inside** the row: `role="option"`, the id, `aria-selected`, the disabled state and the whole key map stay with the component. A slot written where no select reads it says so in dev mode; one that is misspelt cannot be seen at all, and [`lesson-84`](../lessons.md#lesson-84) says why nothing here can                                                                                            |
| **DI contract** | `PCT_FIELD`, and `PCT_TEMPLATE_HOST` provided outwards so a slot below can tell it is home; `fieldAppearance: 'boxed'`, `fieldCursor: 'pointer'`, `activate()` opens the panel                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Strings**     | `placeholder` (when unbound), the empty-list message, the **no-matches** message, the **loading** message, the separator between the chosen labels and the name of the **cross** — all through `PCT_TEXTS`, read at render time ([0014](../decisions/0014-texts-as-signal.md)). Punctuation is a string like any other: an Arabic list is separated by `،`, a Japanese one by `、`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Announced**   | An **empty** panel says so on the library's polite live channel (`PctAnnouncer` in `core`): focus stays on the trigger and an empty listbox gives `aria-activedescendant` nothing to name, so the sentence drawn inside the panel reaches the eye alone ([0026](../decisions/0026-one-channel-per-politeness.md)). A panel a **question** has emptied says the second sentence, `selectNoMatches`, and one whose list is still coming says the third, `selectLoading` — three facts, not three phrasings of one: the first two are conclusions and a request in flight has reached neither. What is withdrawn is what was actually said, when the panel closes, when one sentence replaces another with the panel still open, and when the control is destroyed with it open. A panel **with** options announces nothing — the listbox pattern is already speaking, and a count of matches would need a plural rule                                                                                                              |

## Decisions

[0024](../decisions/0024-the-closing-stack-is-the-dependency-s.md) (the panel's state and its

[0003](../decisions/0003-wrapper-and-control.md), [0007](../decisions/0007-config-and-texts.md),
[0025](../decisions/0025-a-panel-says-whether-it-takes-focus.md) (a press on the panel takes no

consumer of the live channel),
[0028](../decisions/0028-an-icon-set-is-a-component.md) (the arrow is `chevron-down` inside a

it),
[0033](../decisions/0033-an-option-is-a-row-of-data.md) (an option is a row of data — the
projected `<pct-option>` was measured and refused: it types nothing, and it takes the row count
away from the panel),
[0034](../decisions/0034-multiplicity-is-a-tag.md) (multiplicity is a type, so it is a tag —
`pct-multi-select` over one implementation, and the base class this library keeps for exactly
that case),
[0035](../decisions/0035-a-filter-is-a-question-not-a-value.md) (a filter is a question, not a
value: the trigger changes element with the role, the query is panel-scoped, and the value is
read against the whole list),
[0036](../decisions/0036-a-clear-takes-back-what-the-trigger-shows.md) (a clear takes back what
the trigger shows — the cross stands beside the trigger because the parser will not nest two
buttons, and it is out of the tab order because the platform's own clear is),
[0037](../decisions/0037-loading-is-a-fact-about-the-list.md) (loading is a fact about the list,
and a cursor names an option),
[0038](../decisions/0038-a-window-is-measured-and-its-spacer-is-not-an-element.md) (a window is
measured, and its spacer is not an element: the listbox keeps the scroll, the rows nobody drew
are a pseudo-element, and the row's height is read rather than declared)

## Known limitations

- **A windowed list asks for rows of one height, and cannot check it.** The window is
  arithmetic over one measured row, so a label that wraps onto a second line or a
  `pctSelectOption` template drawing two lines moves every row below it. Reported in dev mode
  and not repaired — which of two heights is the right one is the application's question. A
  window and `panelWidth="auto"` are a poor pair for the same reason: "as wide as the longest
  option" is measured from the rows that exist, so the panel would change width as the user
  scrolls.
- **Taking the answer back is not announced.** Focus stays on the trigger and its accessible
  name changes underneath, which no screen reader promises to speak. The honest fix is a
  sentence on the polite channel, and it waits on the measurement this card already records as
  missing — the screen-reader log below.
- **A filtering panel closes by keyboard or by a click outside it, and not by the arrow.** A
  press on a text field is a caret being placed, so the trigger opens and never toggles; the
  arrow is drawn `pointer-events: none` and is a sign rather than a button. `Escape`, `Tab`, a
  pick and an outside click all close it.
- **The matched letters are not highlighted in a row**, and there is no debounce. The row is a
  slot, so a consumer who wants the first has `filterText` and their own template; the second
  belongs to whoever calls a server, because a predicate over an array in memory needs none.
- **A many-choice trigger reads every chosen label, and nothing shortens it.** Long selections
  are cut by the ellipsis the trigger has always had; there is no "3 selected" summary, because
  a count needs a plural rule and a plural rule is not a string — it would be the first thing
  in `PCT_TEXTS` that an application could not translate by handing over a word.
- **A projected `<pct-option>` is not coming.** Measured rather than declined:
  `<pct-option [value]="1">` beside `[value]="'pl'"` compiles silently, the parent's own query
  hands back `any`, and a thousand projected options are a thousand component instances on a
  page whose panel has never opened
  ([0033](../decisions/0033-an-option-is-a-row-of-data.md),
  [`lesson-97`](../lessons.md#lesson-97), [`lesson-98`](../lessons.md#lesson-98)).
- **Duplicate option values are reported, not repaired.** Which option an equal value denotes
  is the application's call, so the component says so in dev mode and leaves the list alone
  ([`lesson-66`](../lessons.md#lesson-66)). What is deliberately **not** measured: that the
  message ever reaches a browser console — no page renders a list with a duplicate, and the
  unit cases carry the proof instead.
- **A row outside the window is outside find-in-page.** That is why `virtual` is opt-in
  rather than a length the library decides for itself: a list that quietly stopped being
  searchable at the four hundredth option would be a defect nobody could report against a
  promise nobody made.
