# `PctAvatar` — the picture beside a name, and never the name itself

**Entrypoint:** `@pacit/components/avatar`
**Selector:** `pct-avatar`
**Status:** released
**ARIA APG pattern:** none — an avatar is decoration, all the way down
([0052](../decisions/0052-an-avatar-is-a-picture-beside-a-name.md)). The host is
`aria-hidden="true"` outright — the third component after `pct-icon` and `pct-skeleton` —
because where an avatar stands the name is already text a reader says, and a second
announcement is noise. Named in the class JSDoc.

What the component owns is the **fallback chain** — image, initials, silhouette, exactly one
standing — and initials that are **graphemes**: the platform's segmenter, because `charAt`
cuts an emoji family or a flag into a broken surrogate half. Both were measured in three
engines before anything was written.

## Contract

|             |                                                                                                                                                                                           |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Value**   | none — a decoration holds no value                                                                                                                                                        |
| **Inputs**  | `name` (`string` — a source for the initials, never an accessible name), `src` (`string` — empty means none), `size` (`PctSize`, from `PCT_CONFIG`)                                       |
| **Outputs** | none — a failed picture is answered by the chain, not announced; nothing else happens to a decoration                                                                                     |
| **Slots**   | **none, deliberately.** The host is `aria-hidden`, and a slot is where a consumer puts a control — the skeleton's argument at the next hidden component                                   |
| **Parts**   | `image` (the photograph, `alt=""`), `initials` (the drawn letters), `silhouette` (the drawing of last resort) — exactly one is in the document at a time                                  |
| **Tokens**  | the `--pct-avatar-*` prefix plus three entries in `contrast.policy.json`                                                                                                                  |
| **Strings** | **none.** The third component in the library to add nothing to `PCT_TEXTS` and therefore nothing to any other entrypoint's bytes — a component that says nothing has nothing to translate |

**Why there is no `alt` input.** A half-decoration with an opt-in voice would be two
components wearing one selector, and the audible one would be wrong wherever the visible
name stands. A control that shows nothing but an avatar names itself — `aria-label` on the
button — which is where the platform puts a control's name anyway; the class JSDoc carries
the example, and the sandbox's last demo shows it.

**Why the initials are not uppercased.** `toLocaleUpperCase()` without a locale answers with
the machine's; with one it needs a locale nobody here knows — the component would be
guessing between `i → I` and `i → İ` on every Turkish name. What the consumer wrote is what
is drawn.

**Why an empty `src` is never bound.** Measured (0052): `src=""` fires `error` in all three
engines — an empty string is a request to the page's own URL, not an absence — so the chain
skips the image element entirely rather than mounting one that is born broken.

## Decisions this component implements

[0052](../decisions/0052-an-avatar-is-a-picture-beside-a-name.md) (the main one — decoration
all the way down, the measured chain, graphemes, the refusals),
[0050](../decisions/0050-a-skeleton-is-a-picture-of-a-wait.md) (the hidden-host shape this
component is the third of, and the shape-as-token move the circle repeats),
[0011](../decisions/0011-icons-are-a-component.md) (the silhouette is `user` in the icon
registry with an inline default — the gate refused the first cut's unswappable `<svg>`, and
the decision records losing that argument),
[0013](../decisions/0013-no-headless-split.md) (parts and tokens as the whole styling
contract — which is why a square avatar is a radius token, not a shape input).

## Known limitations

- **It never speaks, and cannot be made to.** There is no `alt` input on purpose — the name
  belongs to the text or the control beside the picture. A page with truly bare avatars
  names the control that holds them.
- **No status dot.** Presence is a fact with its own text; a coloured dot as its only
  channel fails forced colours and screen readers at once. Where status exists it is the
  page's sentence.
- **No group/stack.** Overflow counts, overlap order and one label for many are a different
  component's questions; refusing them keeps this one a leaf.
- **No loading state.** The box is token-sized either way, so nothing moves when the image
  lands; the initials already stand where the picture is late, and they are a better
  placeholder for a face than motion is.
- **The initials follow words, not scripts' name orders.** First grapheme of first and last
  whitespace-separated word — a CJK full name written without spaces yields one grapheme,
  which is also what those scripts' own conventions draw.
